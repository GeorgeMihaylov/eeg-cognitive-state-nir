# Очистка временных рядов PM-метрик

## Что известно об исходных данных

EMOTIV Cortex возвращает Performance Metrics в диапазоне от 0 до 1. Если
алгоритм не может вычислить метрику из-за низкого качества EEG, значение равно
`null`, а соответствующий `isActive` — `false`. Такие точки не являются
нулевыми значениями когнитивного состояния и должны попадать в пайплайн как
`NaN`, без автоматической интерполяции.

Выгрузки EmotivPRO могут содержать `Raw` и `Scaled` варианты PM. `Scaled`
адаптируется к пользователю по последовательной оценке среднего и дисперсии;
по документации производителя шкала обычно стабилизируется через несколько
минут. Поэтому в одном эксперименте нельзя смешивать `Raw` и `Scaled`, а
начальный дрейф `Scaled` нельзя автоматически объявлять выбросом. Для него есть
параметр `warmup_samples`, который следует задавать по частоте PM конкретной
выгрузки (Cortex предоставляет 0.1 или 2 Гц).

Источники производителя:

- [Cortex API: Data sample object](https://emotiv.gitbook.io/cortex-api/data-subscription/data-sample-object)
- [Cortex API: Data Subscription](https://emotiv.gitbook.io/cortex-api/data-subscription)
- [EmotivPRO: CSV files](https://emotiv.gitbook.io/emotivpro-v3/managing-your-eeg-data-recordings/exporting-an-eeg-data-recording/csv-files)
- [EmotivPRO: Performance Metrics](https://emotiv.gitbook.io/emotivpro-v3/data-streams/performance-metrics)

## Выбранный метод

Пайплайн реализован в `pm_labels.py` и выполняется отдельно для каждой
физической записи:

1. Значения вне заданного диапазона, `inf` и `NaN` отмечаются в
   `invalid_mask` и остаются пропущенными.
2. Одиночные импульсные аномалии обнаруживаются причинным идентификатором
   Hampel: текущая точка сравнивается с медианой предыдущего окна, а масштаб
   оценивается через `1.4826 * MAD`. Медиана и MAD устойчивее среднего и
   стандартного отклонения к самим выбросам. Минимальный абсолютный порог
   решает вырожденный случай `MAD = 0` на почти постоянном участке.
3. По умолчанию аномалии только отмечаются (`outlier_policy="flag"`). Для
   абляции можно заменить только обнаруженные точки локальной медианой или
   перевести их в `NaN`. Отвергнутая точка не попадает в историю детектора.
4. После обработки выбросов можно применить причинную скользящую медиану либо
   простое экспоненциальное сглаживание. Оба варианта используют только прошлое
   текущей записи. На пропуске состояние по умолчанию сбрасывается, чтобы не
   переносить метку через интервал, в котором PM-детектор не работал.

Идентификатор Hampel основан на локальных медиане и MAD и применяется именно к
временным рядам с редкими импульсными отклонениями. Экспоненциальное
сглаживание даёт причинную оценку уровня с постоянным объёмом состояния.

Методические источники:

- [Fried, Bernholt, Gather: Repeated Median and Hybrid Filters](https://doi.org/10.1016/j.csda.2004.12.013)
- [Pearson et al.: Generalized Hampel Filters](https://doi.org/10.1186/s13634-016-0383-6)
- [Brown, Meyer: The Fundamental Theorem of Exponential Smoothing](https://doi.org/10.1287/opre.9.5.673)

## Почему не выбраны другие методы

- Скользящее среднее чувствительно к импульсным выбросам и размазывает их на
  соседние точки.
- Savitzky–Golay и симметричные фильтры используют будущие точки; это неудобно
  для потокового режима и может внести утечку при неосторожной подготовке
  целевых меток.
- Kalman-фильтр требует обоснованной модели динамики и оценок шумов процесса и
  измерения. Без эталонных когнитивных меток такие параметры нельзя надежно
  идентифицировать.
- Заполнение `null` интерполяцией создаёт искусственные обучающие цели в
  интервалах, где производитель прямо сообщает о неработающем детекторе.

## Рекомендуемый запуск

Сначала сохранить исходные метки и получить отчёт без изменения значений:

```python
from cogstate.ingestion import PMCleaningConfig, clean_pm_by_record

audit = clean_pm_by_record(pm, record_ids, PMCleaningConfig())
print(audit.summary())
```

Затем сравнить с робастной очисткой как отдельную абляцию:

```python
config = PMCleaningConfig(
    outlier_policy="local_median",
    outlier_window=7,
    outlier_threshold=3.5,
    min_absolute_deviation=0.05,
    mode="causal_median",
    median_window=3,
    warmup_samples=18,  # примерно 3 минуты только для PM с частотой 0.1 Гц
)
cleaned = clean_pm_by_record(pm, record_ids, config)
```

Параметры следует выбирать до внешней валидации и проверять абляцией
`raw -> flag only -> Hampel replacement -> replacement + smoothing`. Пороговые
значения для перевода непрерывных PM в классы должны вычисляться только на
обучающей части внешнего фолда через `TertileDiscretizer`.

## Продвинутые методы

В `label_denoising.py` реализованы два дополнительных офлайн-метода.
Они работают с непрерывными PM до дискретизации и отдельно обрабатывают каждый
непрерывный участок каждой записи.

### Робастный Student-t Kalman–RTS smoother

Метка представляется как наблюдение скрытого состояния, которое эволюционирует
по модели случайного блуждания. Прямой Kalman-проход оценивает состояние по
прошлым измерениям, а обратный Rauch–Tung–Striebel-проход использует контекст
всей записи. Для устойчивости к выбросам дисперсия каждого наблюдения
итеративно переоценивается весами Student-t:

```text
w[t] = (nu + 1) / (nu + residual[t]^2 / observation_variance)
```

Большой остаток получает малый вес и слабо влияет на скрытое состояние.
`confidence` содержит эти веса, ограниченные единицей, а
`anomaly_mask` отмечает веса ниже `outlier_weight_threshold`.

```python
from cogstate.ingestion import RobustKalmanConfig, denoise_pm_by_record

kalman = denoise_pm_by_record(
    pm,
    record_ids,
    method="robust_kalman",
    config=RobustKalmanConfig(
        process_variance=0.001,
        observation_variance=0.01,
        degrees_of_freedom=4,
    ),
)
```

Основание метода: [Aravkin, Burke, Pillonetto: Robust and Trend-following
Kalman Smoothers using Student's t](https://arxiv.org/abs/1001.3907).

### Huber/L1 trend filtering

Метод решает выпуклую задачу:

```text
min_x sum Huber(y[t] - x[t])
      + lambda1 * ||D1 x||_1
      + lambda2 * ||D2 x||_1
```

Huber loss ограничивает влияние выбросов. L1-штраф первых разностей допускает
редкие скачки уровня, а штраф вторых разностей формирует кусочно-линейные
участки и сохраняет изменения тренда. Задача решается ADMM с разреженной
факторизацией; результат содержит признаки сходимости и число итераций.

```python
from cogstate.ingestion import HuberTrendConfig, denoise_pm_by_record

trend = denoise_pm_by_record(
    pm,
    record_ids,
    method="huber_trend",
    config=HuberTrendConfig(
        huber_delta=0.05,
        first_order_penalty=0.05,
        second_order_penalty=0.5,
    ),
)
```

Основание методов:

- [Kim et al.: L1 Trend Filtering](https://doi.org/10.1137/070690274)
- [Wen et al.: RobustTrend](https://www.ijcai.org/proceedings/2019/0535.pdf)

### Ограничения использования

- Оба метода имеют гиперпараметры, зависящие от частоты PM и ожидаемой скорости
  смены состояния. Их нельзя подбирать по итоговому test-фолду.
- RTS и trend filtering используют будущие PM внутри записи. Они подходят для
  офлайн-подготовки исследовательских меток, но не для причинного real-time
  выхода. Для потокового режима следует оставить только прямой Kalman-проход
  либо причинные методы из `pm_labels.py`.
- Пропуски не интерполируются: каждый `NaN` завершает текущий участок, поэтому
  состояние не переносится через интервал плохого EEG-сигнала.
- `confidence` является внутренней диагностикой метода, а не вероятностью
  правильности когнитивной метки.

Рекомендуемая абляция расширяется до:

```text
raw
-> Hampel flag/replacement
-> causal median/EMA
-> robust Kalman–RTS
-> Huber/L1 trend filtering
```

Сравнивать следует не только итоговую точность модели, но и долю изменённых
меток, сохранность переходов, стабильность по записям и испытуемым, а также
чувствительность результата к параметрам очистки.
