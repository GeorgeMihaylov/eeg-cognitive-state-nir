## Назначение проекта

Проект решает задачу прогнозирования относительного уровня когнитивного показателя Focus по данным ЭЭГ и связанным показателям устройства Emotiv.

Основные цели:

1. создать единый воспроизводимый стенд для сравнения моделей;
2. обеспечить одинаковые разбиения данных для классических и нейросетевых алгоритмов;
3. исключить пересечение испытуемых и логических записей между обучением и проверкой;
4. поддержать несколько представлений данных:
   - агрегированные EEG-признаки;
   - POW-признаки;
   - объединённые EEG+POW-признаки;
   - сырые 10-секундные ЭЭГ-окна;
   - последовательности агрегированных окон;
5. сохранять конфигурации, предсказания, метрики, веса и сведения о разбиениях;
6. исследовать категориальную, порядковую и персонализированную постановки задачи;
7. подготовить основу для селективной калибровки новых пользователей, активного обучения и автоматического выбора стратегии адаптации.

Основная задача классификации:

```text
target: label_q5
number of classes: 5
```

Дополнительно доступна непрерывная цель:

```text
target_focus
```

## Данные

### COG-BCI

Внешний набор COG-BCI содержит 29 участников, три сеанса и 1 044
EEGLAB-записи с частотой 500 Гц. Реализован record-level доступ через
`COGBCIDataset`: детерминированный индекс, фильтрация и ленивое открытие
одной `.set/.fdt`-пары с `preload=False`.

Loader сохраняет нативные layouts: 62 EEG + `ECG1` без `Cz` для участников
1–9 и 63 EEG + `ECG1` с `Cz` для участников 10–29. Он не выполняет
ресемплинг, референсирование, интерполяцию, нарезку окон и создание targets.
Для чтения EEGLAB необходима опциональная зависимость:

```powershell
python -m pip install "mne>=1.12,<2"
```

Window materialization и научные задачи COG-BCI пока не реализованы.

## Формирование целевой переменной

`target_focus` основан на показателе Focus устройства Emotiv и агрегируется внутри 10-секундного окна.

`label_q5` формируется квантильным разбиением `target_focus` на пять уровней:

```text
0 < 1 < 2 < 3 < 4
```

Это слабая порядковая разметка, а не клиническая или экспертная аннотация когнитивного состояния.

Аудит цели показал:

- около 84% вариативности находится внутри испытуемых;
- около 16% связано с различиями между испытуемыми;
- коэффициент внутриклассовой корреляции составляет около 0,16;
- автокорреляция соседних окон составляет около 0,88;
- через 10 окон сохраняется корреляция около 0,44;
- пересчёт квантильных границ только по обучающей части меняет около 2,7% меток;
- согласованность исходных и пересчитанных меток по quadratic weighted kappa составляет около 0,99.

Высокая временная зависимость объясняет, почему случайное перемешивание окон существенно завышает качество.

## Протокол оценки

### Основной научный протокол

```yaml
evaluation:
  protocol: group_kfold_subject
  n_splits: 5
  group_column: subject_id
```

Используется пятифолдовый `GroupKFold` по `subject_id`.

Свойства:

- один испытуемый не встречается одновременно в обучении и внешнем тесте;
- каждый пример попадает во внешний тест один раз;
- модель создаётся заново для каждого фолда;
- внешние индексы одинаковы для сравниваемых моделей;
- нормализация рассчитывается только по обучающей части;
- внутренняя проверка строится только внутри внешней обучающей части;
- внешний тест не используется для выбора эпохи, архитектуры или гиперпараметров.

Для сырых данных внутренняя проверка разделяется по независимому от источника `record_group_id`.

### Вложенный выбор гиперпараметров

Для вспомогательной CORN-задачи использовались:

```text
lambda = 0.25, 0.5, 1.0
```

Для каждой комбинации группы признаков, начального значения генератора и внешнего фолда обучались три кандидата.

```text
2 feature groups × 3 seeds × 5 folds × 3 lambdas = 90 fits
```

Правило выбора:

1. сбалансированная точность кандидата может быть ниже парной категориальной модели не более чем на 0,01;
2. среди допустимых кандидатов минимизируется доля тяжёлых ошибок;
3. затем минимизируется порядковая средняя абсолютная ошибка;
4. при равенстве выбирается меньшее значение `lambda`.

Внешний тест использовался только после завершения выбора.

### Случайное оконное разбиение

Случайное стратифицированное разбиение сохранено только как техническая проверка конвейера. Его результаты нельзя интерпретировать как качество переноса на нового пользователя.

### Порядковые варианты Transformer

- категориальная голова;
- CORAL;
- CORN;
- совместная `categorical_corn`.

Совместная архитектура:

```text
Transformer encoder
├── categorical head: 5 logits
└── auxiliary CORN head: 4 conditional logits
```

Функция потерь:

```text
L_total = L_categorical + lambda × L_CORN
```

Основной прогноз формируется категориальной головой. Вспомогательная голова используется только как регуляризующая задача.

- уменьшает порядковую среднюю абсолютную ошибку;
- уменьшает долю ошибок более чем на один класс;
- немного снижает сбалансированную точность;
- демонстрирует компромисс между категориальным и порядковым качеством.

## Главный научный вывод текущей ветки

Гипотеза о том, что вспомогательная CORN-задача позволит одновременно сохранить категориальную точность и уменьшить тяжёлые порядковые ошибки, не подтвердилась.

```text
selected decision: not_supported
```

Получен устойчивый конфликт целей:

- категориальный Transformer предпочтителен для balanced accuracy и macro F1;
- чистый CORN предпочтителен для ordinal MAE и severe-error rate;
- совместная функция потерь не стала доминирующим компромиссом;
- единый глобальный вес вспомогательной задачи не подходит всем испытуемым;
- дальнейший перебор `lambda` в текущей архитектуре не является приоритетным.

Результат является содержательным отрицательным результатом и мотивирует переход от одной глобальной модели к персонализированному выбору стратегии.

## Воспроизводимость и защита от утечек

В проекте зафиксированы следующие ограничения:

- внешний тест отделяется по `subject_id`;
- внутренняя проверка строится только внутри внешнего обучения;
- логические записи не пересекаются между внутренним обучением и проверкой;
- статистики нормализации оцениваются только на обучающей части;
- состояние модели не переиспользуется между фолдами;
- сравниваемые модели используют одинаковые внешние индексы;
- выбор `lambda` выполняется только по внутренней проверке;
- внешний тест не используется для выбора ветви политики;
- результаты всех 90 кандидатов проходят аудит;
- при финализации модели не переобучаются;
- статистическая единица итогового анализа — испытуемый;
- три начальных значения генератора усредняются внутри испытуемого и не считаются независимыми наблюдениями;
- все сравнения категориального Transformer, CORN и политики используют точно совпадающие внешние последовательности.

## Ограничения

1. `label_q5` является слабой разметкой, основанной на показателе устройства.
2. Показатель Focus не является независимой экспертной оценкой когнитивного состояния.
3. Число испытуемых ограничено 53 участниками последовательностного анализа.
4. Абсолютное качество межсубъектного переноса остаётся умеренным.
5. `GroupKFold` не гарантирует стратификацию классов между фолдами.
6. Пять категориальных резервных вариантов были добавлены как прозрачная поправка после исходных защитных прерываний и не должны описываться как заранее зарегистрированное правило.
7. Совместная категориально-порядковая модель не подтвердила основную гипотезу.
8. Несогласие двух голов не является проверенным правилом назначения калибровки.
9. Межисточниковая оценка не тождественна полноценному переносу между разными устройствами.
10. Для межаппаратного переноса требуется внешний набор данных с другой конфигурацией устройства или каналов.
11. Сырые CNN пока не моделируют длительный межоконный контекст.
12. Полный регрессионный трек для `target_focus` не завершён.

## Следующий этап

Следующее приоритетное направление — селективная персональная калибровка модели для новых пользователей.

Предлагаемая постановка:

1. оценить качество общей модели без калибровки;
2. определить, требуется ли адаптация конкретному пользователю;
3. оценить ожидаемый выигрыш от калибровки;
4. выбрать минимальный объём наиболее информативных данных;
5. выбрать стратегию адаптации:
   - без дообучения;
   - только выходная голова;
   - частичное размораживание кодировщика;
   - полное дообучение;
   - категориальная или порядковая функция потерь;
6. остановить калибровку при исчерпании ожидаемого выигрыша.

Активное обучение должно отвечать за выбор примеров, а автоматический выбор конфигураций — за решение о необходимости и способе адаптации.

Основной вывод текущей ветки: категориальный Transformer и чистый CORN оптимизируют разные свойства качества.
